# Scott.F.N Personal Hub

Live site: https://nsc9ab-ops.github.io/crypt-secure-workspace/

A futuristic, local-first personal workspace with a calendar, camera capture, QR/barcode home inventory, a private file vault, local financial record signing, current-device location, and appearance settings. A Firebase-backed Members area supports verified accounts, deterministic usernames that can be generated offline for accounts already signed in on the device, friend requests, live text messages, and foreground voice-call signaling after a Firebase project is configured. The local Cyber Arcade includes two games, plus Kenya Highway PRO, a landscape truck-driving game with route-specific Rift Valley, lake, mountain, savannah and tea-terrace scenes, a curved corner exit, a raised expressway flyover, rivers and bridges, matatu stages, moving pedestrians and weighbridge checkpoints, traffic lights, zebra crossings, steering-wheel and tilt controls. Kenya Highway PRO is split into HTML, CSS and JavaScript files, with GLSL terrain shading and a C++ vehicle-physics core compiled to WebAssembly during the Pages build. It includes pointer-responsive controls, 60 Hz physics, native display-refresh rendering, live FPS reporting, and adaptive render resolution. Games are cached for offline play after the first load.

The LIFEKEEP starter structure is included as a command-centre view for finances, savings goals, home intelligence, smart shopping, shared life, calendar/tasks, protection, trusted devices, and settings. Its demo structure links into Scott.F.N's existing local modules. A password screen sets a local browser access lock. Messages, cycle notes, and financial signatures are encrypted locally with AES-GCM after password unlock. During first setup the app creates a recovery code that can change the password while preserving encrypted records; save that code in a password manager or offline safe because the app cannot recover a lost code. Other app state and uploaded files remain local browser data and are not encrypted at rest. The emergency erase code `@254` permanently erases this device’s Scott.F.N local data; it is not a recovery method. The connection badge reports the browser's online/offline status.

The site is published through GitHub Pages using the `Publish Scott.F.N website` workflow. Financial files, notes, location, and signatures remain in the user’s browser; uploaded files are not encrypted at rest. A local signature is not identity verification or payment authorization. Once the Firebase project and supplied Firestore rules are configured, Firebase Authentication and those rules protect member chats. Messages are not end-to-end encrypted. Do not use the chat for passwords, verification codes, financial credentials, or sensitive health data.

The supplied Scott.F.N emblem is used for the website, installed PWA, and Android launcher icon. The Android APK download is published at [downloads/ScottFN.apk](https://nsc9ab-ops.github.io/crypt-secure-workspace/downloads/ScottFN.apk). It is a debug-signed WebView wrapper around the live website. After its first successful online load, the service worker caches the app shell and local Firebase SDK bundle so supported browsers and Android 7+ WebView can reopen the app and local sections offline. First installation and updates still need internet; new sign-ins, phone verification, live member sync, and calls need a connection. Firestore can show previously loaded member data offline and sync queued changes after reconnection. Its browser cache can remain after sign-out, so use a trusted, private device. Android requests camera, microphone, and location permissions only when those features are opened. The camera page offers selfie and back-camera selection. Profile pictures are kept on the device. Cycle records stay in that app installation's browser storage.

The Phone security section is part of the same Scott.F.N app. It opens Google's official Remote Lock and Find Hub tools for a lost Android phone. Enable Remote Lock ahead of time on the phone under Settings → Google → All services → Theft protection, and keep a screen lock, active SIM, and internet connection available. Google handles account verification and device actions; Scott.F.N does not collect Google passwords or location data.

## Firebase member service setup

The repository includes the client integration, `firestore.rules`, and `firestore.indexes.json`. The published site shows setup instructions until a Firebase Web app config is added to `firebase-config.js`. A Firebase project must be created in the owner's Google account; this repository cannot create or link the project automatically.

1. Create a Firebase project and register a Web app. Copy its Web config values into `firebase-config.js` (`apiKey`, `authDomain`, `projectId`, and `appId`). Firebase Web config is public client config; never add Admin SDK keys or service account credentials.
2. In Firebase Authentication, enable Phone sign-in, configure the SMS region policy, and add `nsc9ab-ops.github.io` to the authorized domains. If the member form reports `configuration-not-found` or `operation-not-allowed`, Phone sign-in is not enabled; open the Authentication setup link shown on the Members page.
3. Create a Cloud Firestore database.
4. Install the Firebase CLI, authenticate with the project owner account, then deploy the included rules and index: `firebase deploy --only firestore --project YOUR_PROJECT_ID`.
5. Publish the updated site. Each signed-in Firebase account gets a deterministic username derived from its unique account ID, even when the device is offline. Its full encoded account ID makes the username collision-free; when internet returns, the app reserves it in Firestore so other verified members can search it. Existing short usernames remain valid aliases. A friend request must be accepted before messaging or calling.

Voice calls use WebRTC. The included public STUN server may not connect peers on every network; add TURN through a provider or protected token service for broader reach. Do not put permanent TURN credentials in this public site. Firebase signaling supports calls while the app is open; background ringing and push notifications are not included.

Until a real Firebase project config and deployed rules are supplied, account creation, cross-device messaging, and calls remain inactive. The existing local chat notes continue to be stored on the device.
